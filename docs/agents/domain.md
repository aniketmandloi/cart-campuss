# Domain docs

## Before exploring

Read root `GLOSSARY.md` and relevant decisions in `docs/adr/`.

If these files do not exist, proceed silently. The domain-modeling skill
creates them when terms or decisions are resolved.

## Layout

This repo uses a single context:
- `GLOSSARY.md`: domain terminology.
- `docs/adr/`: architectural decision records.

## Vocabulary and decisions

Use glossary terms in issue titles, proposals, hypotheses, and tests.
Reconsider unfamiliar terms or note real gaps for domain-modeling.

Surface conflicts with existing ADRs explicitly, identifying the ADR
and why its decision may need reopening.
